## 2024-06-25 - Batched Async Monitoring Interval Pile-up
**Learning:** The application uses Next.js `instrumentation.ts` to run a globally scoped `setInterval` for the background uptime monitoring task (`runChecks` in `src/lib/monitoring.ts`). Previously, it processed multiple monitors using a sequential `for...of` loop with `await`. In a large database, executing synchronous I/O blocks sequentially within an interval can cause interval pile-ups, exhausting available threads or resulting in staggered scheduling. Using unbounded `Promise.all` can similarly overwhelm database connection pools or API rate limits.
**Action:** Always process heavy external I/O tasks within intervals using chunked concurrent execution (e.g., slicing an array into batches of 10 and executing `await Promise.allSettled(batch.map(...))`). Also, specifically with `Promise.allSettled`, remember to iterate over the returned results and explicitly handle `status === 'rejected'` to prevent unhandled promise rejections and silently swallowed errors.
