## 2025-06-20 - Concurrent Webhook Alert Dispatch Optimization
**Learning:** Webhook alerts were previously dispatched sequentially inside a `for...of` loop in `src/lib/alerts.ts`. Because `fetch` calls await the network response, this created a hidden O(N) performance bottleneck where the total wait time scaled linearly with the number of webhook rules configured for a monitor. This could significantly delay the final alert in the chain and tie up application execution.
**Action:** Always dispatch network requests concurrently using `Promise.all` combined with `Array.prototype.map` when the requests are independent. Crucially, wrap individual operations inside the `map` with their own `try...catch` blocks so that one failed request (e.g., a dead webhook endpoint) does not reject the entire `Promise.all` batch and block subsequent notifications.
